Equals vs. Identity

Two names can hold the same value, or point at the very same object. == asks the first question and is asks the second.

The picture: names are sticky notes

An object is a thing in memory, like the number 5 or a list. A name is a sticky note you stick onto an object. a = 5 does not put 5 inside a. It sticks the label a onto a 5.

  • b = a sticks a second label onto the same object. It does not make a new one.
  • c = b looks at what b is stuck to right now, and sticks c there too.
  • b = 7 peels b off, and sticks it on a different object. Other labels stay where they were.

Two questions you can ask

OperatorQuestion
a == bDo they hold equal values?
a is bAre they the same object? (Same place in memory.)

If a is b is True, then a == b is True as well. The other way round is not guaranteed: two separate lists with the same contents are equal, but they are not the same list.

Where it really matters: lists

Numbers cannot be changed in place, so sharing one is harmless. A list can be changed in place, so two names on one list is a real thing to watch. Press Step through: the memory view is already switched on, so you will see which names share an object.

a = [1, 2]
b = a
b.append(3)
print(a)
print(a is b)
A small caution about numbers and strings

Python sometimes reuses small numbers and short strings, so x is y can be True even when you made them separately. That is an implementation detail you should never rely on. Use == to compare values. The real use for is is x is None, and the exam-style questions about which names share an object.
