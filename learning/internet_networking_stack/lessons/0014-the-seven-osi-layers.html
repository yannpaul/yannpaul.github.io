The Seven OSI Layers

A name for the ladder this whole course has been climbing, plus a way to hold it in memory.

"Layer 2," "Layer 4," "Layer 7" — this course has used all three by name, in Lessons 3, 6, 7, 8, and 9, without ever laying out the full model they come from. This lesson closes that gap: the complete seven-layer stack, one course example tied to each layer that has one, and a mnemonic for keeping all seven straight.

The idea underneath all seven layers

Each layer is defined by how much of a packet a device is willing to look at to make its forwarding decision. The higher the layer, the more of the actual content gets read. Layer 1 only cares that a signal exists at all; Layer 7 reads the full request and understands what it means.

Why Layers 5 and 6 feel unfamiliar

That's normal, not a gap in what you've learned. Real-world protocols don't cleanly map to one OSI layer each — TLS (Lesson 5) blends what the model calls Session and Presentation concerns into one thing; HTTP folds Session-like behavior (cookies, keep-alive) into an Application-layer protocol. This is exactly why this course, and most working engineers, talk almost exclusively in L2 / L3 / L4 / L7 shorthand: those are the layers with a distinct, nameable piece of software doing the work (a bridge, a router, a Service, a gateway). Layers 5 and 6 are still correct, official parts of the model — they're just rarely the layer anyone points to when describing a real system, this one included.

Holding all seven in memory

Bottom to top — Physical, Data Link, Network, Transport, Session, Presentation, Application — the standard mnemonic is:

"Please Do Not Throw Sausage Pizza Away"

Top to bottom, the common alternative is "All People Seem To Need Data Processing" (Application, Presentation, Session, Transport, Network, Data Link, Physical) — useful if you prefer thinking from the request's intent down to the wire, which is closer to how this course actually walked through the stack (Lesson 9's Kong reading intent, down through Lesson 7's Service, down to Lesson 8's bridge).

In "Please Do Not Throw Sausage Pizza Away," which word corresponds to the layer Lesson 3's route tables operate at?

  • "Do" (Data Link)
  • "Please" (Physical)
  • "Not" (Network)
  • "Throw" (Transport)

Think first: name one concept from this course that lives at Layer 2, one at Layer 3, one at Layer 4, and one at Layer 7 — without looking back at the table above.

Layer 2: the cni0 bridge (Lesson 8) switching frames between Pods on the same node by MAC address. Layer 3: a route table's longest-prefix-match decision (Lesson 3), or BGP underlay Pod routing (Lesson 8) — both forward by IP address across networks. Layer 4: a Kubernetes Service and kube-proxy (Lesson 7) — matches ClusterIP and port, nothing more. Layer 7: Kong, whether as a plain gateway (Lesson 6) or as Ingress Controller (Lesson 9), reading the actual Host header and path to decide where a request goes. If any of these didn't come to mind immediately, that lesson is worth a quick re-read before the capstone.
