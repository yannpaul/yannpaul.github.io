Upgrading to Cobra

Rebuild Lessons 1–10 from memory first. Then replace the whole hand-rolled dispatch tree with github.com/spf13/cobra — the library answer to everything getConfig and friends have been doing by hand.

Cobra is the de facto standard for nested CLI subcommands in Go — it's what powers kubectl, hugo, gh, and a long list of other real tools. Every mechanic you've built by hand since Lesson 4 — a command tree, per-subcommand flags, "unknown subcommand" errors — Cobra does natively, plus one thing you've never had: real --help text, generated automatically from the exact same code that parses your flags.

Warm-up — repeat from Lessons 1–10
  • Checkpoint

    find name, du top, perm check, perm who, and every "expected a subcommand"/"unknown subcommand" error all behave the same as always.

New: installing Cobra

  • Stuck? Show the command 
    go get github.com/spf13/cobra
    Checkpoint

    go.mod now has require lines for github.com/spf13/cobra and its own dependencies (spf13/pflag, inconshreveable/mousetrap) — the first time this course has depended on anything outside the standard library.

A Cobra command is one type, *cobra.Command, used two ways: as a leaf that does something (it has a RunE) or as a container for subcommands (you call .AddCommand(...) on it, and it has no RunE of its own). Building the same tree you already have by hand means building one *cobra.Command per verb, nesting them with AddCommand.

  • Set SilenceErrors: true and SilenceUsage: true on the root command — without them, Cobra prints its own "Error: ..." line and a full usage dump on every failure, which fights with the error format this course has used since Lesson 1.

    Stuck? Show the skeleton 
    func main() {
	rootCmd := &cobra.Command{Use: "burrow", SilenceErrors: true, SilenceUsage: true}

	// subcommands added below

	if err := rootCmd.Execute(); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
}

    Add "github.com/spf13/cobra" to your import block. Leave findName, sizeOf, duTop, checkPerm, and whoOwns exactly as they are — none of your actual logic changes today, only what calls it.

    Checkpoint

    go build succeeds. Running burrow with no arguments now prints Cobra's own auto-generated usage listing and exits 0 — different from your old "expected a subcommand" error and its exit code 1. That's an intentional, reasonable difference, not a bug to chase: no subcommands are registered yet, so there's nothing else to do.

New: find, built fully as the worked example

  • cmd.Flags().String(name, default, usage) registers a flag on that specific command, the same idea as flag.NewFlagSet from Lesson 4 — but reading the value back inside RunE needs cmd.Flags().GetString(name), which returns the value and an error (safe to ignore here — it only fails if you typo the flag's name, a programmer mistake you'd catch immediately, not a runtime condition).

    Stuck? Show the code 
    findCmd := &cobra.Command{Use: "find"}
findNameCmd := &cobra.Command{
	Use: "name",
	RunE: func(cmd *cobra.Command, args []string) error {
		path, _ := cmd.Flags().GetString("path")
		pattern, _ := cmd.Flags().GetString("pattern")
		return findName(path, pattern)
	},
}
findNameCmd.Flags().String("path", ".", "path to search")
findNameCmd.Flags().String("pattern", "*", "glob pattern to match filenames against")
findCmd.AddCommand(findNameCmd)
rootCmd.AddCommand(findCmd)
    Checkpoint

    burrow find name --pattern "*.go" works exactly as before. Now try the same command with a single dash: burrow find name -pattern "*.go" — it fails, with an error about an unrecognized shorthand flag. That's expected; see the idiom callout below.

Idiom

Cobra's flags are built on spf13/pflag, not the standard library's flag package — and pflag draws a real distinction Lesson 2 told you didn't exist: a single dash is reserved for one-letter shorthand flags (-h for --help, which every Cobra command gets for free), and a long flag name always needs a double dash. -pattern isn't read as "the pattern flag" — pflag tries to parse it as a run of one-letter shorthands (-p -a -t -t -e -r -n) and fails on the first one that isn't registered. This is a genuine, common trip-up moving from stdlib flag to almost any other Go flag library, pflag included.

New: du and perm, the same shape — your turn

  • Stuck? Show the code 
    duCmd := &cobra.Command{Use: "du"}
duTopCmd := &cobra.Command{
	Use: "top",
	RunE: func(cmd *cobra.Command, args []string) error {
		path, _ := cmd.Flags().GetString("path")
		n, _ := cmd.Flags().GetInt("n")
		return duTop(path, n)
	},
}
duTopCmd.Flags().String("path", ".", "path to inspect")
duTopCmd.Flags().Int("n", 10, "how many entries to show")
duCmd.AddCommand(duTopCmd)
rootCmd.AddCommand(duCmd)
    Checkpoint

    burrow du top --n 5 behaves exactly as before.

  • Stuck? Show the code 
    permCmd := &cobra.Command{Use: "perm"}
permCheckCmd := &cobra.Command{
	Use: "check",
	RunE: func(cmd *cobra.Command, args []string) error {
		path, _ := cmd.Flags().GetString("path")
		return checkPerm(path)
	},
}
permCheckCmd.Flags().String("path", ".", "path to inspect")
permWhoCmd := &cobra.Command{
	Use: "who",
	RunE: func(cmd *cobra.Command, args []string) error {
		path, _ := cmd.Flags().GetString("path")
		return whoOwns(path)
	},
}
permWhoCmd.Flags().String("path", ".", "path to inspect")
permCmd.AddCommand(permCheckCmd, permWhoCmd)
rootCmd.AddCommand(permCmd)
    Checkpoint

    burrow perm check --path . and burrow perm who --path . both behave exactly as before.

New: what you get for free

  • Checkpoint

    Each one prints real, accurate usage text — burrow find name --help specifically lists --path and --pattern with their descriptions and defaults, generated straight from the Flags().String(...) calls you wrote. Nothing in this course's hand-rolled version ever had this — you would have had to write and maintain it by hand, separately from the flags themselves, and it would have drifted out of sync eventually.

  • Checkpoint

    go build still succeeds with all of that gone — proof it was genuinely dead code, not something quietly still relied on. What's left: your five logic functions (findName, sizeOf, duTop, checkPerm, whoOwns, plus the small helpers each uses) and main's Cobra tree. Config is gone entirely — each RunE reads its own flags directly, so there's no longer one struct threading values through getConfig/run to get there.

Idiom

Every RunE above returns error, not Run's no-return-value form — which exists in Cobra too, and would have quietly let a failure inside findName or duTop vanish the same way Lesson 7's opening bug did. RunE is what keeps this course's oldest standing rule intact through a whole library swap: an error is a value, and something must always look at it.

burrow now has the same five commands, the same behavior, real generated help text, and roughly a third less hand-written dispatch code than it had this morning. Lesson 12 puts actual tests around the logic functions that haven't changed through any of this — findName's pattern matching and duTop's size math are exactly as testable now as they were before Cobra existed.

Something unclear — why RunE over Run, the single-dash/double-dash distinction, why deleting Config entirely is safe, anything else? Ask your teacher (me) before moving on.
