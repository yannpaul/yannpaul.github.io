New: a Config to hold a -path flag

getConfig() currently configures nothing. Today it earns its name: it will read a -path flag from the command line (defaulting to ., the current directory) and hand it to run() inside a small struct.

Go's standard library ships this in the flag package. The shape you'll use: flag.String(name, defaultValue, usage) registers a flag and immediately returns a *string — a pointer, not the value itself, because the real value doesn't exist until you call flag.Parse(), which reads os.Args and fills in every registered flag's pointer.

  • Stuck? Show the type 
    type Config struct {
	Path string
}

  • Remember flag.String gives you a *string — you'll need to dereference it (*pathFlag) to put the value into your Config.

    Stuck? Show the function 
    func getConfig() (Config, error) {
	path := flag.String("path", ".", "path to inspect")
	flag.Parse()
	return Config{Path: *path}, nil
}

    Add "flag" to your import block.

  • Stuck? Show the function 
    func run(cfg Config) error {
	fmt.Println("burrow: inspecting", cfg.Path)
	return nil
}
  • Stuck? Show the function 
    func main() {
	cfg, err := getConfig()
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	if err := run(cfg); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
}

Now prove it works three different ways:

  • Checkpoint

    go run . prints burrow: inspecting . — the default takes over when you don't pass -path.

  • Checkpoint

    go run . -path=/tmp prints burrow: inspecting /tmp.

  • Checkpoint

    go run . -path /tmp prints the exact same thing as the = form. Both syntaxes are accepted for non-boolean flags — see the idiom box below for why that's not true of every flag type.

Idiom

Go's flag package accepts a single dash for every flag — -path, not --path — though it tolerates a double dash too, since it only looks at how many leading dashes there are, not what they conventionally mean elsewhere. The -flag=value and -flag value forms are interchangeable for string, int, and most other flag types, but not for booleans: -verbose false doesn't work the way you'd expect, because flag treats a bare -verbose as already having consumed its value (true) and then tries to parse false as a positional argument instead. -verbose=false is the only reliable way to set a bool flag to false. You'll hit this directly once a boolean flag shows up later in the course.

This flag.String / flag.Parse pair is the exact call shape you'll reuse for every subcommand once burrow grows a real command tree — the only thing that changes in Lesson 4 is that each subcommand gets its own flag.NewFlagSet instead of sharing the single global one flag.Parse() uses here. The getConfig-then-run shape doesn't change at all.

Something unclear — why flag.String returns a pointer, the -path=x vs. -path x vs. boolean-flag gotcha, why Config exists instead of just reading the flag straight from run, anything else? Ask your teacher (me) before moving on.
