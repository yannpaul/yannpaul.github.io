New: actually looking at the filesystem

Everything so far has treated cfg.Path as a plain string — burrow never actually opened it. That changes today, using filepath.WalkDir: it walks a directory tree, calling a function you provide once for every file and directory it finds, starting with the root itself.

The function you hand it has a fixed shape: func(path string, d fs.DirEntry, err error) error. path is the full path to the current entry; d describes it (name, whether it's a directory, and more, from the io/fs package); err is non-nil if WalkDir couldn't even read that entry (e.g. a permission error) — you decide what to do about it. Your function's own return value controls what happens next: nil continues, filepath.SkipDir skips the rest of a directory without stopping the whole walk, and any other error stops everything and comes back out as WalkDir's own return value.

  • Inside your callback: if the err parameter is non-nil, return it immediately (don't try to print a broken entry). Otherwise print path and return nil.

    Stuck? Show the function 
    func walk(root string) error {
	return filepath.WalkDir(root, func(path string, d fs.DirEntry, err error) error {
		if err != nil {
			return err
		}
		fmt.Println(path)
		return nil
	})
}

    Add "io/fs" and "path/filepath" to your import block.

    func run(cfg Config) error {

Idiom

filepath.WalkDir replaced an older function, filepath.Walk, which is still around but shouldn't be reached for in new code. The difference: Walk's callback receives an os.FileInfo, which requires a full stat system call for every single entry — expensive on a large tree. WalkDir's callback receives a lighter-weight fs.DirEntry that already has the name and directory-or-not bit without stating anything; you only pay for a full Stat() call if you explicitly ask d.Info() for one. For a tool like burrow that may walk large trees (Lesson 6's disk-usage report will stat every file on purpose, but find shouldn't have to), that difference matters.

Also worth noticing now, because it'll matter the moment burrow needs to skip anything: your callback gets a chance to react to every entry, including directories, before WalkDir descends into them. Returning filepath.SkipDir when d.IsDir() is true skips that whole subtree — the mechanism a later lesson will use to skip things like .git.

Something unclear — the callback's exact signature, when to return filepath.SkipDir versus a plain error, why WalkDir beats hand-rolled recursion, anything else? Ask your teacher (me) before moving on.
