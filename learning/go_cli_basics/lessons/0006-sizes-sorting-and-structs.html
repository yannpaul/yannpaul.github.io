Sizes, Sorting, and Structs

Rebuild Lessons 1–5 from memory first. Then give du the exact same nested-dispatch treatment find got in Lesson 5 — and make it actually report something.

Today: burrow du top --n 5, an ncdu-style report of the biggest entries under a path. The dispatch mechanics are nothing new — Lesson 5's recipe, applied to du instead of find. What's new is the actual work: measuring file sizes, and sorting.

    func getFindConfig() (Config, error) {
	if len(os.Args) < 3 {
		return Config{}, fmt.Errorf("expected a find subcommand: name")
	}

	switch os.Args[2] {
	case "name":
		fs := flag.NewFlagSet("find name", flag.ExitOnError)
		pattern := fs.String("pattern", "*", "glob pattern to match filenames against")
		path := fs.String("path", ".", "path to search")
		fs.Parse(os.Args[3:])
		return Config{Command: "find name", Path: *path, Pattern: *pattern}, nil
	default:
		return Config{}, fmt.Errorf("unknown find subcommand %q", os.Args[2])
	}
}

  • Note this is a different struct from Config — Config holds what the CLI was told to do; dirSize holds one measurement your code produces while doing it. Don't reuse Config for this.

    Stuck? Show the type 
    type dirSize struct {
	Name string
	Size int64
}

  • d.IsDir() tells you whether an entry is a directory. For files, call d.Info() to get an fs.FileInfo, then .Size() on that.

    Stuck? Show the function 
    func sizeOf(root string) (int64, error) {
	var total int64
	err := filepath.WalkDir(root, func(path string, d fs.DirEntry, err error) error {
		if err != nil {
			return err
		}
		if d.IsDir() {
			return nil
		}
		info, err := d.Info()
		if err != nil {
			return err
		}
		total += info.Size()
		return nil
	})
	return total, err
}

  • Use sort.Slice — it takes your slice and a "less" function you write yourself, so you control the ordering directly instead of needing a named type that implements an interface. Guard against n being bigger than the number of entries you actually found.

    Stuck? Show the function 
    func duTop(root string, n int) error {
	entries, err := os.ReadDir(root)
	if err != nil {
		return err
	}

	var sizes []dirSize
	for _, entry := range entries {
		path := filepath.Join(root, entry.Name())
		size, err := sizeOf(path)
		if err != nil {
			return err
		}
		sizes = append(sizes, dirSize{Name: entry.Name(), Size: size})
	}

	sort.Slice(sizes, func(i, j int) bool {
		return sizes[i].Size > sizes[j].Size
	})

	if n > len(sizes) {
		n = len(sizes)
	}
	for _, s := range sizes[:n] {
		fmt.Printf("%10d  %s\n", s.Size, s.Name)
	}
	return nil
}

    Add "sort" to your import block.

Idiom

sort.Slice doesn't return anything — it sorts sizes in place, using your "less" function (func(i, j int) bool) every time it needs to compare two elements by their index. Writing sizes[i].Size > sizes[j].Size (greater-than, not less-than) is what makes the sort descending — a common trip-up, since "less" functions almost always default to reading as ascending unless you deliberately flip the comparison like this.

Notice what didn't need to change: sizeOf reuses the exact same filepath.WalkDir shape from Lessons 3 and 5, just accumulating a number instead of printing or matching. Three lessons in a row have now reached for the same tool for a different job — that's the pattern to internalize, not any one lesson's specific code.
