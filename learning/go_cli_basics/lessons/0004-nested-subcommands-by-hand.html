func walk(root string) error {
	return filepath.WalkDir(root, func(path string, d fs.DirEntry, err error) error {
		if err != nil {
			return err
		}
		fmt.Println(path)
		return nil
	})

	return walk(cfg.Path)
}

func main() {
	cfg, err := getConfig()
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	if err := run(cfg); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}

New: a subcommand per verb

Right now every flag has to come before any positional argument, and there's only ever one thing burrow can do. A real nested CLI reads its first argument as a verb — find, du, or perm — and only that verb's own flags after it. Go's standard library supports this directly: instead of the single global flag.Parse() you used in Lesson 2 (which parses flag.CommandLine, one shared set for the whole program), flag.NewFlagSet(name, flag.ExitOnError) creates an independent flag set you control yourself — you decide which slice of os.Args it parses.

That's the other new piece: os.Args, the raw command-line arguments as a []string. os.Args[0] is always the program's own path — not a flag, not a subcommand. os.Args[1] is where a verb like find would land. Everything from os.Args[2:] onward belongs to that verb's own flag set.

Idiom

Why bother with a separate flag.NewFlagSet per subcommand instead of just keeping Lesson 2's single flag.Parse()? Because the package-level flag.CommandLine parses starting from os.Args[1] and stops at the first argument that doesn't look like a flag — which means find itself would stop it cold, and -path would have to come before the verb (burrow -path . find) to be seen at all. That's backwards from how real nested CLIs read. Giving each subcommand its own flag set, parsing only os.Args[2:], is what makes burrow find -path . — verb first, its own flags after — actually work.

This is the exact mechanism Lesson 5 reuses to go one level deeper: find itself will grow a second verb (find name --pattern ...), parsed out of os.Args[2:] the same way find was just parsed out of os.Args[1:]. Once that lands, burrow find name --pattern "*.go" is the foo bar baz --arg val shape from the mission, done by hand with nothing but the standard library.

Something unclear — why os.Args[0] isn't the subcommand, why the global flag.Parse() breaks with subcommands, why du and perm get full Config plumbing before they do anything, anything else? Ask your teacher (me) before moving on.
