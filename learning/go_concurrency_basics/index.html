Go Concurrency Through burrow

Learn goroutines and channels by fixing a real bottleneck in burrow, the CLI tool from Go CLI Basics: du top currently scans every subdirectory one at a time. Same format as that course — a checklist, not a script, with code hidden behind collapsed disclosures until you're stuck.

Nine lessons, each a self-contained page. Every lesson (from Lesson 2 on) opens by making you redo everything structural from prior lessons before teaching anything new. Only Lessons 1–2 are written so far; the rest are scoped below and will be built out in future sessions. This workspace assumes you already have a working burrow — built across Go CLI Basics' lessons — on your own machine; lessons here tell you what to change in that existing code.

Lessons

  1. Your First Goroutine — the go keyword, why it doesn't wait for anything, and sync.WaitGroup as the fix, on a small standalone demo before touching burrow
  2. Goroutines That Do Real Work — parallelize duTop's directory scanning for real: one goroutine per entry, an indexed slice write to collect results race-free, and a mutex-protected error so Lesson 7's "never discard an error" still holds
  3. Coming up — Share Memory By Communicating — introduce channels as Go's preferred alternative to a shared variable plus a lock, and send duTop's results over one instead
  4. Coming up — A Real Data Race, On Purpose — deliberately break duTop with an unsynchronized append, catch it with go run -race, and see exactly why Lesson 2's indexed-write pattern never had this problem
  5. Coming up — Buffered vs. Unbuffered Channels — when a send actually blocks, and what changes (and doesn't) when a channel has room
  6. Coming up — select and Timeouts — read from more than one channel at once, and bound how long du top will wait on a slow subdirectory
  7. Coming up — Worker Pools: Bounded Concurrency — why "one goroutine per file" breaks down on a huge tree, and a fixed pool of workers pulling work off a channel instead
  8. Coming up — Upgrading to errgroup — replace the by-hand WaitGroup + mutex-protected-error pattern with golang.org/x/sync/errgroup, the real-world library answer, mirroring how go_cli_basics moved from by-hand dispatch to cobra
  9. Coming up — Capstone: Concurrent burrow, Race-Free and Benchmarked — pull every technique together, compare serial vs. parallel wall-clock time on a large test tree, and defend every synchronization choice in the finished code
