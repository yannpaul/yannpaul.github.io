The logic ladder from your notes

  1. not happens first
  2. and
  3. or happens last

That is a ladder inside the bigger ladder from Lesson 1. All of arithmetic, containment, comparison and identity happen before any of these three.

A single = is assignment. A double == is the question “are these equal?”. Mixing them up is the most common beginner error.

The one place your class ladder and real Python disagree

Your notes put in, == and is on separate rungs. In real Python they share one rung, and a run of them chains: 1 < x < 10 means 1 < x and x < 10. The surprise is that this also applies to in and ==. Try it, then do the exam-trap problem about it below.

x = 7
print(1 < x < 10)
print(x > 3 and not x == 7)
print(5 in [1, 5] == True)
A good habit

When a condition has more than two parts, write the value of each comparison underneath it before you touch not, and or or. On a test, this is the whole trick.
