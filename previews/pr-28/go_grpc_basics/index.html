gRPC and Protobuf in Go

Learn Protocol Buffers and gRPC by building logline, a small event-log service, from a schema file to a real client and server talking over the network. Same format as Go CLI Basics and Go Concurrency Basics — a checklist, not a script, with code hidden behind collapsed disclosures until you're stuck.

Nine lessons, each a self-contained page. Every lesson (from Lesson 2 on) opens by making you redo everything structural from prior lessons before teaching anything new. Only Lessons 1–2 are written so far; the rest are scoped below and will be built out in future sessions. Unlike the two prior Go workspaces, this one doesn't reuse burrow — a client and server talking over a real connection, generated from a schema file, is different enough to deserve its own small project.

Lessons

  1. Protobuf Basics — what a .proto file is, write logline's first message, generate real Go code from it with protoc, and read what came out
  2. Your First Unary RPC — add a service to the .proto file, generate client/server stubs, implement Append, and run a real client against a real server over a real TCP connection
  3. Coming up — More Unary RPCs and Idiomatic Errors — add Get, then replace a bare Go error with gRPC's status/codes package, the idiomatic way to report "not found" versus "something broke"
  4. Coming up — Server Streaming — List and Tail: a single request, many replies streamed back over one call
  5. Coming up — Client Streaming — BatchAppend: many requests streamed up, a single summary reply
  6. Coming up — Bidirectional Streaming — Sync: both sides streaming to each other over the same call, at once
  7. Coming up — Deadlines, Cancellation, and context — propagate a client's deadline into the server's context.Context, and see what happens on both sides when it's exceeded
  8. Coming up — Interceptors — gRPC's equivalent of HTTP middleware: log or authenticate every RPC in one place instead of repeating code in every method
  9. Coming up — Capstone: logline, End to End — pull every RPC shape together into one complete, defensible service and client
